# 00 — charter: tebako versions (the catalog site)

Owner-locked direction (2026-09-08): a standalone project that renders a
mise-versions.jdx.dev-style catalog of the tebako ecosystem's published
artifacts, hosted at **https://www.tebako.org/versions** via GitHub Pages.
This directory (`~/src/tamatebako/versions/`) is the project's local home;
the plans in `TODO.impl/` are the execution contract. Execute them in
number order; each plan lands behind its own PR.

## What this is

A **static, read-only rendering** over data the ecosystem ALREADY publishes.
No new publishing machinery, no server, no database. The build fetches from
three public data planes and emits static HTML:

1. **Factory releases** (GitHub releases API):
   - `tamatebako/tebako-runtime-ruby` — releases like `v0.16.22` carry ~800
     assets: per (ruby line × platform triplet) an interpreter exe
     (`tebako-runtime-<tebakoVer>-<langVer>-<triplet>[.exe]`), the env image
     (`….tfs`), a per-runtime `….manifest.json`, and one checksum file.
     VERIFIED: the checksum asset is `SHA256SUMS.txt` in this repo.
   - `tamatebako/tebako-runtime-python` — `v0.1.1` (2026-09-08): 122 assets,
     CPython lines 3.11.16 / 3.12.14 / 3.13.15 / 3.14.7 × 6 POSIX triplets
     (macos-arm64, macos-x86_64, linux-gnu-{x86_64,arm64},
     linux-musl-{x86_64,arm64}). Checksum asset name UNVERIFIED here — accept
     both `SHA256SUMS` and `SHA256SUMS.txt`.
2. **Feedstock registries** (`tpkg-registry.yaml` at the root of each repo in
   the `tebako-packages` org — e.g. `tebako-packages/xml2rfc`): the L3 mirror
   of resolution fields (payload versions, entrypoints, runtime requirements,
   artifact URLs + sha256). These files are REGENERATED by
   `tebako publish --registry-out`; the site reads, never writes.
3. **Product releases** (`tamatebako/tebako`): the toolchain itself — version,
   per-platform `tebako-bootstrap` asset SIZE (there is a < 3 MiB CI gate on
   the loader; displaying the number is the point).

## Decision log (locked — do not relitigate)

- **Hosting**: `www.tebako.org/versions`, GitHub Pages. The exact mechanics
  (org-pages subpath vs assemble-into-the-main-deploy) are decided in
  `03-github-pages-hosting.md` AFTER verifying how tebako.org's Pages is
  configured — both paths are written there.
- **No runtime JSON API.** The no-default-service law stands;
  `tebako-resolve` already talks to registries directly. This site is for
  humans. (Machine consumers use the registries/releases directly.)
- **No standalone domain for now.** `versions.tebako.org` is a later owner
  decision; the subpath choice is the reversible step.
- **SSOT (spec 00 invariant 10)**: the site NEVER re-authors a contract
  value. Everything rendered is either fetched from a published source or
  derived with the derivation rule shown on the page with a link to its
  owning source. The one derivation (capability chips, e.g. `yjit`) is
  scheduled to become a FLOWED value when the factories publish a
  `capabilities:` manifest key — that migration is plan 04.
- **Audience rule**: a viewer of the site needs nothing — static HTML, no
  JS-required rendering (filter/copy are progressive enhancement).

## Invariants for every plan

- YAML for authored config (`sources.yaml`); JSON only for generated data.
- Named failures, never silent partial data: if a source fails after
  retries, the BUILD FAILS LOUDLY (a stale-looking half-catalog is worse
  than a failed deploy; the previous deploy stays live).
- Net-flake tolerance: retry with backoff on 403-rate-limit / 5xx / TLS /
  DNS errors (this network has a captive portal that hijacks TLS
  intermittently — 3 retries, 5/15/45 s backoff, then fail).
- Commits: `GIT_EDITOR=true git -c user.name=tebako-ci -c
  user.email=tebako@ribose.com commit`. PR bodies via `--body-file` only.
- One open PR at a time; draft until CI green; merges to `main` of THIS repo
  are fine once green (the repo publishes nothing until plan 03 turns Pages
  on), but the tebako.org-side assembly change (if path B) and the Pages
  enablement are production — those stay draft until the owner's go-ahead.
